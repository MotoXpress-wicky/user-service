**1. `POST /api/auth/forgot-password` (Requesting the Reset)**

**Input:** User's `email` address.

* **Step 1: Immediate Generic Response:** Instantly return an HTTP 200 Success status and a generic message (e.g., *"If an account with that email exists, we have sent a password reset link"*).
* **Step 2: Hand-off to Background:** Pass the actual database lookup and email sending to an asynchronous background thread so the response time doesn't leak whether the email is real.
* **Step 3: Database Lookup:** (In the background) Check if the provided email exists in the database.
* **Step 4: Silent Abort:** If the email does **not** exist, do nothing and stop the process entirely.
* **Step 5: Invalidate Old Tokens:** If the email **does** exist, find and delete (or mark invalid) any existing unused reset tokens for this user so only the newest one will work.
* **Step 6: Generate Token:** Generate a cryptographically secure, random 256-bit string.
* **Step 7: Hash & Store:** Run that raw string through SHA-256. Store only this hashed version in your `password_reset_tokens` database table, linked to the user, with an expiration time set to 15-30 minutes from now.
* **Step 8: Send Email:** Send the actual email containing a frontend link with the **raw** token attached (e.g., `[https://yourapp.com/reset-password?token=RAW_TOKEN_HERE](https://yourapp.com/reset-password?token=RAW_TOKEN_HERE)`).

---

**2. `POST /api/auth/reset-password` (Submitting the New Password)**

**Input:** The raw `token` (from the URL) and the `newPassword`.

* **Step 1: Hash the Incoming Token:** Take the raw `token` provided in the request and run it through SHA-256 so you can compare it against your database.
* **Step 2: Database Lookup:** Search the `password_reset_tokens` table for that exact hash.
* **Step 3: Validation Checks:**
* If the token hash is **not found** $\rightarrow$ Return error ("Invalid or expired token").
* If the token is **expired** (current time > expiration time) $\rightarrow$ Return error.
* If the token is already **marked as used** $\rightarrow$ Return error.


* **Step 4: Update Password:** If all checks pass, take the `newPassword`, hash it using BCrypt, and update the user's password record in the database.
* **Step 5: Burn the Token:** Mark the current reset token as "used" (or delete it) so it can never be used again. Delete any other outstanding tokens for this user.
* **Step 6: Invalidate Sessions:** Log the user out of all existing devices. (If using stateless JWTs, this usually means incrementing a `tokenVersion` or `securityStamp` on the user record so all old JWTs are rejected).
* **Step 7: Send Notification:** Trigger a background task to send a "Your password was just changed" security email to the user.
* **Step 8: Success Response:** Return a 200 OK message to the frontend instructing the user to log in with their new password.
